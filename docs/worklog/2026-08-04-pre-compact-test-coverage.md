# 計画

`tests/test_pre_compact.py` の各ケースを `.codex/hooks/pre_compact.py` の実行経路と
現行仕様へ対応付け、単なる行・分岐の通過と、仕様違反を検出できるアサーションの強さを
分けて評価する。既存のユーザー変更と実装・テスト本体は変更しない。

# 仮説と検証結果

- 仮説: 小規模な hook なので実行行と主要分岐はほぼ通るが、出力物の意味まで確認する
  アサーションには不足がある。
- 検証結果: `python3 tests/test_pre_compact.py` は4件すべて成功した。
- 検証結果: transcript が存在する分岐、存在しない分岐、ローテーションの削除ループが
  0回と複数回の経路、stdout に鮮度警告を出さない回帰動作は実行されている。
- 検証結果: ローテーションは残存数しか検証せず、最古を削除して新規スナップショットと
  最新9件を残す意味的な正しさは検証していない。

# 発見

- `test_snapshot_created` はコピー件数と本文を確認するが、ファイル名の日時・turn ID・
  12文字切り詰めを確認しない。
- `test_rotation_keeps_10` は削除対象を誤っても件数が10なら成功する。上限直前・上限時の
  境界も個別には確認しない。
- `test_missing_transcript_is_noop` は終了コードだけを確認し、保存先を作らないこと、
  stdout/stderr が空であることを確認しない。
- `test_stale_notes_no_warning` は廃止済み警告の重要な回帰テストだが、`strip()` 後の
  stdout のみを確認するため、厳密な無出力や stderr は対象外である。
- malformed JSON、非object payload、欠落/空/長い/パス区切りを含む turn ID、読み書き
  失敗、同一秒・同一turnのファイル名衝突、並行実行は未検証である。hook payload を
  信頼する契約なら一部は低優先だが、衝突とローテーション対象の正しさは保存目的へ
  直接影響する。

# 判断とその理由

- 総合評価は「実行経路の網羅性は高いが、仕様アサーションと堅牢性の網羅性は中程度」と
  する。主要な真偽分岐とループは通る一方、誤った成果物でも通過するケースがあるため。
- 追加するなら、(1) ローテーション後のファイル名集合、(2) ファイル名契約と turn の
  default/切り詰め、(3) missing transcript の完全な no-op、(4) 衝突・異常入力の期待契約、
  の順を推奨する。最初の3件は現行仕様を直接固定し、費用対効果が高い。
- 古い記録には鮮度警告が現役という説明が残るが、現行実装・2026-08-04設計・テストを
  原典として、警告廃止後の仕様で評価した。
